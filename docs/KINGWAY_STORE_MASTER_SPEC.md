# KINGWAY 매장관리시스템 마스터 스펙 v2
**목적:** 이 문서는 KINGWAY 독립 매장관리시스템의 최상위 기준 문서다.  
앞으로 Codex / Claude Code / 개발자는 이 문서를 기준으로 기능을 설계·수정한다.  
앞으로는 전체 시스템을 다시 설명하지 않고, **수정사항만 말해도 되도록** 시스템 목적, 승인 흐름, UX/UI 기준, LINE 연동 규칙, 데이터 규칙을 모두 여기 고정한다.

---

# 0. 이 문서의 해석 원칙

1. 이 문서는 **실제 운영 목적** 기준이다.
2. 화면에 보이는 모든 문구는 **대만 중국어번체(zh-TW)** 기준으로 한다.
3. 고객/직원/공급사 흐름의 중심은 **LINE**이다.
4. 고객은 **LINE 안에서 최대한 끝나야** 한다.
5. 직원은 **웹/모바일 + LINE 그룹 승인 흐름**으로 빠르게 처리해야 한다.
6. 수리/구매/쿠폰/CRM/재고/발주/반품/직원관리/정산이 **한 시스템에서 이어져야** 한다.
7. 향후 에이전트는 임의로 영어 UI, 임의 워크플로우, Telegram 복귀 구조를 만들면 안 된다.
8. 이 문서가 기존 임시 패치보다 우선이다.

# 2. 핵심 철학

## 2-1. 고객 경험
- 매장 방문 시 직원은 LINE 친구추가를 유도한다.
- 고객은 전화번호를 반복 입력하지 않게 한다.
- 구매확인서, 수리예약, 견적확인, 설문, 쿠폰 등은 **LINE 안에서 쉽게 끝나야** 한다.
- 고객은 “지금 내가 무엇을 해야 하는지”만 명확하게 보이면 된다.

## 2-2. 직원 경험
- 직원은 메뉴를 헤매지 않고 **지금 처리할 일**을 바로 볼 수 있어야 한다.
- 승인/거절/완료/발주/반품/교차확인은 **버튼 중심**이어야 한다.
- 웹/모바일 모두 사용 가능해야 한다.
- LINE 그룹 알림에서 바로 업무 흐름으로 이어져야 한다.

## 2-3. 운영 경험
- 상태 변경이 생기면 관련자에게 즉시 알림이 가야 한다.
- 고객 데이터는 CRM 중심으로 계속 누적되어야 한다.
- 구매/수리/쿠폰/리뷰/설문/재고/정산/직원 KPI가 서로 끊기지 않아야 한다.

예:
- Dashboard → 儀表板
- Customers → 客戶管理
- Orders → 訂單管理
- Repairs → 維修管理
- Inventory → 庫存管理
- Purchase Confirmations → 購買確認書管理

- Settlement → 結算管理
- KPI → 員工績效

내부 enum이 영어라도 **보이는 카테고리는 반드시 번체 중국어**로 표시한다.

권장 표기:
- EBIKE → 電動自行車

- OTHER → 其他

## 6-1. 신규 친구 쿠폰

# 7. 구매 관리

## 7-1. 당일 완납 구매
1. 직원이 POS에서 주문 입력
2. 고객 전화번호가 LINE 바인딩 고객인지 확인
3. 사용 가능한 쿠폰 확인
4. 결제 완료
5. 고객에게 LINE으로 **購買確認書 버튼** 발송
6. 고객이 구매확인서 작성 / 서명 / 제출
7. 직원 LINE 그룹에 `購買確認書已完成` 알림
8. 직원이 `確認交車` 버튼을 누른 후 자전거를 인도

## 7-2. 구매확인서 규칙
- EBIKE 구매 고객 대상
- 고객명 / 전화번호 / 주문정보 자동 표시
- 고객이 전화번호를 다시 입력하지 않음
- 서명 필수
- 제출 후 PDF 생성
- PDF는 고객관리 메뉴에서 다운로드 가능
- PDF에는 서명이 포함되어야 한다

## 7-3. 예약주문 / 예약금 / 미납금
예약주문은 일반주문과 다르게 관리한다.

주문에는 최소 표시:
- 是否預約單
- 訂金金額
- 未付款金額
- 完款狀態
- 最終付款日期

흐름:
1. 예약금만 먼저 결제
2. 주문은 예약주문 상태로 저장
3. 자전거 도착 후 미납금 납부
4. 직원이 `未付款補收` / `完成尾款` 처리
5. 완납되면 최종 결제 완료 상태
6. 이후 구매확인서 LINE 제출 흐름으로 진행

## 7-4. 주문 관리 화면
필수 분류:
- 一般訂單
- 預約訂單
- 訂金未清
- 已付款待確認
- 已完成交車

표시 항목:
- 주문번호
- 고객명
- 전화번호
- 주문상품
- 총액
- 예약금
- 미납금
- 결제상태
- 구매확인서 상태
- 쿠폰 사용 여부

# 8. 수리 관리

## 8-1. 수리 예약 신청
조건:
- LINE 친구추가 완료
- 전화번호 바인딩 완료

고객 입력:
- 預約日期
- 預約時間
- 車種
- 維修內容

고객이 제출하면:
- 직원 LINE 그룹에 알림
- 직원이 `確認` / `拒絕`
- 결과를 고객에게 안내

## 8-2. 수리 주문 판정 규칙
**수리 카테고리 상품이 주문에 하나라도 있으면 그 주문은 수리 주문이다.**

이 주문은:
- 일반 주문 메뉴만이 아니라
- **維修管理**에서도 관리되어야 한다.

## 8-3. 수리 견적
직원이 수리메뉴에서 견적 입력:
- 維修項目
- 零件
- 工資
- 預估完成時間
- 備註

견적 입력 후:
- 고객 LINE으로 견적서 발송
- 고객이 `同意` / `拒絕`
- 고객 응답이 직원 LINE 그룹에 알림
- 동의 후 수리 시작

## 8-4. 수리 완료
직원이 `維修完成` 버튼을 누르면:
- 고객 LINE으로 “비용 지불 후 자전거를 수령하라”는 알림
- 같은 알림에 **수리 설문 버튼** 제공

## 8-5. 수리 설문
고객이 설문을 완료하면:
- 수리메뉴에 해당 고객 설문 결과 버튼 표시
- 직원이 클릭해서 열람 가능
- 필요시 관리자에게도 알림

## 8-6. 수리 상태 예시
- 已預約
- 待檢查
- 待報價確認
- 維修中
- 維修完成待取車
- 已取車
- 已取消

# 18. 이 버전(v2)에서 추가로 명확히 고정한 사항

이 버전은 이전 버전보다 아래를 더 명확히 고정한다.

1. 고객 유입 후 **LINE 환영사에서 CRM 질문을 진행**
2. 전화번호 제공 시 **500원 쿠폰 즉시 발급**
3. Google 리뷰 쿠폰은 **직원 확인 후 발급**
4. 고객이 리뷰 완료 버튼을 누르면 **직원 LINE 그룹에 승인/거절 버튼**
5. 수리 예약도 동일하게 **LINE 그룹 승인 흐름**
6. 수리 견적은 고객 LINE 확인/거절 → 직원 그룹 알림 구조
7. 수리 완료 시 고객에게 수령 안내 + 설문 버튼
8. 설문 결과는 수리메뉴에서 버튼으로 열람
9. EBIKE 구매 당일 완납 시 구매확인서 LINE 제출 + PDF 저장
10. 예약금 주문은 **예약금 / 미납금 / 완납** 구조로 명확히 관리
11. 고객관리에 주문/수리/CRM 단계/문서 히스토리 누적
12. 상품관리/재고/발주/반품/공급사 승인 흐름 전부 LINE과 연결
13. 직원 출퇴근 / KPI / 매일 체크리스트 / 월정산 구조 포함
14. 모든 상태 변화는 관리자 LINE 그룹에 정리 알림 가능해야 함
