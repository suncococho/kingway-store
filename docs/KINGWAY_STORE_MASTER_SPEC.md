# KINGWAY 매장관리시스템 마스터 스펙
**파일 목적:** 앞으로 Codex / Claude Code / 개발자가 KINGWAY 독립 매장시스템을 수정할 때, 이 문서를 **최상위 기준 문서**로 삼는다.  
**핵심 목표:** 앞으로는 전체 시스템을 다시 설명하지 않고, **수정사항만 말해도 되도록** 업무 목적, UX/UI 방향, 데이터 규칙, 승인 흐름, LINE 연동 방식을 한 문서에 고정한다.

---

## 0. 최상위 원칙

1. **고객/직원/공급사 연동의 중심은 LINE이다.**
2. **사용자 화면의 모든 문구는 대만 중국어번체(zh-TW) 기준**으로 한다.
3. **웹 + 모바일 동시 사용**이 가능해야 한다.
4. **고객은 최소 입력, 직원은 최소 클릭**으로 처리한다.
5. **상태 변경은 즉시 알림**이 가야 한다.
6. **고객 데이터는 CRM 중심으로 누적**되어야 한다.
7. **주문 / 수리 / 쿠폰 / 재고 / 공급사 / 직원 KPI / 정산**이 하나의 시스템 안에서 이어져야 한다.
8. **EBIKE / 수리 / 일반상품**은 화면상 의미가 명확히 구분되어야 한다.
9. **수리 카테고리 상품이 주문에 하나라도 있으면 그 주문은 수리 주문으로 판정**한다.
10. **Google 리뷰 쿠폰은 자동 발급 금지, 직원 확인 후 발급**이 원칙이다.
11. **구매확인서 / 수리견적 / 설문 / 쿠폰 / 예약 알림은 LINE 안에서 끝나도록 설계**한다.
12. **개발 에이전트는 이 문서를 기준으로 수정**하고, 불명확한 경우에만 최소한으로 질문한다.

## 1. 시스템 정체성

### 1-1. 시스템 이름
**KINGWAY 台南 獨立門市管理系統**

## 3. UX/UI 총원칙

### 3-1. 화면 언어
**모든 사용자 노출 텍스트는 대만 중국어번체로 표시한다.**  
예:
- Dashboard → 儀表板
- Customers → 客戶管理
- Orders → 訂單管理
- Repairs → 維修管理
- Inventory → 庫存管理
- Attendance → 出勤管理
- KPI → 員工績效
- Settlement → 結算管理

### 3-2. 직원 UX 원칙
- 직원은 복잡한 메뉴 탐색 없이 **현재 해야 할 일**부터 보여야 한다
- 승인/거절/완료/발주/반품은 **버튼 중심**
- LINE 알림에서 바로 처리 가능해야 한다
- “待確認 / 待處理 / 今日重點”가 첫 화면에 보여야 한다

### 3-3. 고객 UX 원칙
- 고객은 LINE에서 바로 이해 가능해야 한다
- 고객은 전화번호를 반복 입력하지 않게 한다
- 구매확인서, 수리견적, 설문, 쿠폰은 **한 번의 클릭 후 제출**
- 고객은 “내가 지금 무엇을 해야 하는지”만 보이면 된다

### 3-4. 모바일 우선
- 관리자 페이지는 모바일에서도 조작 가능해야 한다
- 상품 등록, 사진 업로드, 고객조회, 수리 상태변경, 발주/반품 등록이 모바일에서도 가능해야 한다

### 3-5. 기록 누적형 UI
- 고객 1명 클릭 시:
  - 기본 정보
  - LINE 바인딩 상태
  - 쿠폰 내역
  - 주문 히스토리
  - 수리 히스토리
  - 설문 히스토리
  - CRM 단계 및 접촉 히스토리
  를 한눈에 볼 수 있어야 한다

## 4. 고객 유입 / LINE 친구추가 / CRM 흐름

### 4-1. 매장 방문 시 첫 단계
직원은 손님에게 **LINE 친구추가**를 유도한다.

### 4-2. 친구추가 후 환영 흐름
환영사에서 CRM 질문을 진행한다:
- 預算大約多少？
- 大概什麼時候想購買？
- 主要用途是什麼？
- 是否願意留下手機號碼？

### 4-3. 전화번호 제공 시 혜택
전화번호를 제공하면:
- 고객 전화번호를 LINE과 바인딩
- **NT$500 쿠폰** 발급
- 사용 조건:
  - **EBIKE 카테고리 상품 구매 시만 사용 가능**
  - 1인 1회
  - 동일 고객 중복 발급 금지

### 4-4. CRM 단계 저장
고객관리에는 최소 아래를 저장:
- LINE userId
- 이름
- 전화번호
- 예산
- 구매 예상 시점
- 사용 목적
- CRM 단계
- 마지막 접촉일
- 담당 직원
- follow-up 예정일

### 4-5. 미구매 고객 follow-up
LINE 친구추가만 하고 아직 미구매인 고객은:
- 3일
- 7일
- 14일
단위로 자동/수동 follow-up 가능해야 한다.

고객관리에서 직원이 버튼으로 실행:
- 3日追蹤
- 7日追蹤
- 14日追蹤
- 手動發送

## 5. 쿠폰 시스템

### 5-1. 신규 친구 쿠폰
- 금액: **NT$500**
- 조건: 전화번호 제공 + LINE 바인딩 완료
- 사용처: **EBIKE 카테고리만**
- 1인 1회
- 사용/발급 이력 저장

### 5-2. Google 리뷰 쿠폰
- 금액: **NT$1500**
- 고객은 LINE 안에서 “我已完成 Google 評論” 버튼 또는 리치메뉴를 누른다
- 직원 LINE 그룹에 알림
- 직원이 실제 리뷰를 확인 후:
  - `確認發券`
  - `拒絕`
- 확인 누르면 고객에게 발급
- 사용 조건:
  - **EBIKE 카테고리만**
  - 1인 1회
  - 발급/사용 이력 저장

### 5-3. 쿠폰 관리 화면
고객별로 보여야 함:
- 已發券
- 已使用
- 未使用
- 失效
- 券種別（新好友 / Google 評論）
- 發券時間
- 核准員工

## 6. 구매 관리

### 6-1. 일반 당일 구매
1. POS에서 주문 입력
2. 고객 전화번호가 LINE 바인딩된 고객인지 확인
3. 쿠폰 사용 가능 여부 확인
4. 결제 완료
5. 고객 LINE으로 **구매확인서 버튼** 발송
6. 고객이 클릭해서 구매확인서 작성 / 서명 / 제출
7. 직원 LINE 그룹에 `購買確認書已完成` 알림
8. 직원이 `確認交車` 클릭 후 자전거 인도

### 6-2. 구매확인서
조건:
- EBIKE 주문이어야 함
- 전화번호가 있어야 함
- LINE 바인딩 고객이어야 함
- 고객은 다시 전화번호 입력하지 않음
- 고객명, 전화번호, 주문번호, 구매 상품, 금액 자동 표시
- 서명 필수
- 제출 후 PDF 생성
- PDF는 고객관리 메뉴의 해당 고객 화면에서 다운로드 가능

### 6-3. 예약주문 / 예약금 / 미납금
예약주문 구조:
- 주문에는 반드시 아래가 보여야 함
  - 是否預約單
  - 訂金金額
  - 未付款餘額
  - 完款狀態
- 예약금 결제 후 주문 저장
- 자전거 도착 후 미납금 결제 버튼 제공
- 직원이 `未付款補收` 또는 `完成尾款` 처리
- 완납이 되면 최종 결제 완료 상태로 전환
- 이후 구매확인서 LINE 제출 흐름으로 이어짐

### 6-4. 구매 관리 화면
필수 기능:
- 訂單搜尋
- 已付款 / 訂金未清 / 已完成交車 / 待購買確認
- 고객별 주문 히스토리
- 구매확인서 PDF 다운로드
- EBIKE / 配件 / 其他 필터
- 예약주문과 일반주문 구분

## 7. 수리 관리

### 7-1. 수리 예약 신청
조건:
- LINE 친구추가 완료
- 전화번호 바인딩 완료
- 고객이 LINE 안에서 예약 신청

입력 항목:
- 預約日期
- 預約時間
- 車種
- 維修內容
- 聯絡方式

고객이 확인을 누르면:
- 직원 LINE 그룹에 알림
- 직원이 `確認` / `拒絕`
- 확인 시 고객에게 예약 확정 안내
- 거절 시 고객에게 재선택 안내

### 7-2. 수리 주문 판정 규칙
**주문에 수리 카테고리 상품이 하나라도 있으면 그 주문은 수리 주문으로 판정한다.**  
이 주문은 일반 주문 메뉴가 아니라 **維修管理** 기준으로 보여야 한다.

### 7-3. 수리 견적 입력
고객이 매장에 오면 직원이 수리메뉴에서 견적 입력:
- 維修項目
- 零件
- 工資
- 預估完成時間
- 備註

입력 후:
- 고객 LINE으로 견적서 발송
- 고객은 `同意` / `拒絕`
- 고객 응답이 오면 직원 LINE 그룹에 알림
- 승인 후 수리 시작

### 7-4. 수리 진행
상태 예시:
- 已預約
- 待檢查
- 待報價確認
- 維修中
- 維修完成待取車
- 已取車
- 已取消

### 7-5. 수리 완료
직원이 수리메뉴에서 `維修完成` 버튼을 누르면:
- 고객 LINE에 “비용 지불 후 자전거 수령” 알림 발송
- 같은 알림에 **수리 설문조사 버튼** 제공

### 7-6. 수리 설문
고객이 설문을 완료하면:
- 수리메뉴에서 해당 고객의 설문 결과를 버튼으로 열람 가능
- 낮은 점수는 관리자 LINE 그룹에 알림

### 7-7. 수리 관리 화면
한 고객 클릭 시:
- 예약 정보
- 견적서
- 고객 응답
- 수리 진행 로그
- 완료일
- 비용
- 설문 결과
- 수리 히스토리
표시 가능해야 함

## 9. 상품 관리

## 10. 재고 / 발주 / 반품 관리

### 10-1. 재고관리
- 상품 선택
- 현재고 표시
- 入庫 / 出庫 / 調整
- 이력 기록

### 10-2. 발주
직원이 재고관리 메뉴에서:
- 상품 선택
- 수량 입력
- 메모 입력
- 발주 버튼 클릭

그러면:
- 공급사 LINE 그룹에 알림
- 공급사가 `確認` / `拒絕`
- 상태 기록

### 10-3. 입고 확인
상품이 매장에 도착하면:
- 직원이 발주된 항목별로 각각 확인 버튼 클릭
- 부분입고 / 전체입고 가능
- 재고 자동 반영

### 10-4. 반품
직원이:
- 상품 선택
- 수량
- 사유
- 메모 입력
- 반품 요청

그러면:
