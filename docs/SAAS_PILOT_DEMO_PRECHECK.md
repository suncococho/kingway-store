# SaaS 파일럿 매장 데모 운영자 최종 점검표

## 1. 데모 전 30분 체크
- [ ] 데모 예정 시간 기준 30분 전 기준 시각을 팀 전체에 공유
- [ ] 점검 대상 매장: `kw_rehearsal_owner`(demo 전용) / `store_id=5` 사용 확인
- [ ] Chrome, Safari, Android/iOS 브라우저에서 데모 URL 접속 가능 여부 사전 확인
- [ ] 네트워크 지연/VPN/방화벽 등 외부 접속 차단 요소 점검
- [ ] 타임라인 준비: 데모 진행자/보조자 역할 분담 및 휴대폰 대기 상태 확인
- [ ] 데모 시나리오 문서(`SAAS_PILOT_STORE_DEMO_SCRIPT.md`)와 최종 체크리스트(`SAAS_V1_FINAL_LAUNCH_CHECKLIST.md`) 최신본 확인

## 2. smoke script 실행
- [ ] `docs/SAAS_REGRESSION_EXECUTION_RUNBOOK.md`에 따라 재실행
- [ ] 데모 직전 기준 점검용으로 최소 1회 전체 재실행
- [ ] 기대 결과: `PASS=16 / FAIL=0 / SKIP=0` (또는 운영 규격 변경 시 최신 승인값)
- [ ] 실패 건은 항목별 스크린샷/로그 식별자와 함께 즉시 기록
- [ ] 결과 캡처는 사용자 전달용 요약본만 보관하고 raw password/token 미포함

## 3. 데모 계정 준비
- [ ] 오너 계정: `kw_rehearsal_owner` 로그인 정상 여부 확인
- [ ] 데모용 staff 계정/권한(최소 1명) 점검: 상점 설정/상품 등록/주문/수리관리 접근 가능
- [ ] 고객용 LINE 가짜번호/테스트 데이터(비식별) 준비
- [ ] 데모 계정 로그인/비밀번호는 운영자 외 노출 금지
- [ ] 데모 중 계정 잠김/캡차/비밀번호 변경 이슈가 없도록 상태 확인

## 4. 데모 URL 준비
- [ ] 데모 공유 URL: 스테이징 기본 URL + 데모 경로 명확히 확정
- [ ] 북마크/초대 메시지용 URL은 공용 문서에 미리 등록
- [ ] 동일 URL에서 staff/owner 뷰 분기 확인(권한별 화면 확인)
- [ ] POS/결제/문의 화면 진입 경로는 실사용자가 따라가기 쉬운 경로로 준비

## 5. 보여줄 데이터 준비
- [ ] 매장 생성/설정 화면의 기본값(매장명, 영업시간, 알림 규칙) 준비
- [ ] LINE 설정 완료 상태(테스트 채널 또는 스테이징 모드) 확인
- [ ] 상품 등록용 샘플: EBIKE/REPAIR/ACCESSORY/OTHER 분류 데이터 각 1개 이상
- [ ] 주문/POS 데모용 샘플 주문서 1건 이상 생성
- [ ] 수리예약-승인/추정/완료 흐름 샘플 준비
- [ ] 구매확인 PDF 생성 데모용 주문 데이터(비식별) 준비
- [ ] Free/Premium 플랜 차이점 비교용 요약 카드 준비

## 6. 보여주면 안 되는 데이터
- [ ] 실제 영업 데이터(실제 주문/매출/고객) 마스킹 또는 숨김
- [ ] 실제 고객 휴대폰, 개인정보, 구매 이력
- [ ] 운영 실환경 정책/금전성 민감 정보(실제 환불/정산 내역 등)
- [ ] production token, API 키, DB 접속정보가 UI/공유문서에 노출되지 않음

## 7. LINE 발송 금지 확인
- [ ] 데모 전 `실제` LINE 메시지 발송 기능이 비활성(혹은 테스트 수신자 제한)인지 확인
- [ ] 데모 중 버튼/플로우에서 실제 메시지 발송이 발생하지 않도록 절차 안내
- [ ] 데모 진행자 휴대폰으로 “발송 금지 모드” 및 테스트 채널 설정 동의 확인
- [ ] 메시지 발송이 필요한 동작은 화면 캡처 또는 설명으로 대체

## 8. production .env/token 비노출 확인
- [ ] 데모 시작 전 `.env` 파일(특히 `*_TOKEN`, `*_SECRET`, DB credential) 오픈 노출 여부 점검
- [ ] 채팅방/화면 공유용 문서에서 production 키·환경변수 삭제 상태 확인
- [ ] 실행 로그 저장 시 토큰/비밀번호 패턴 마스킹 확인
- [ ] 데모 중 로그/캡처 공유 채널을 운영자 1인 승인 후 전송

## 9. 실패 시 데모 중단 기준
- [ ] smoke script에서 FAIL 발생(특히 로그인, 결제/주문, 수리 승인/완료, 구매확인 경로)
- [ ] 데모 계정 로그인 실패 또는 권한 미노출 발생
- [ ] 데모 URL 접속 불가 또는 결함으로 핵심 시나리오가 실행되지 않는 경우
- [ ] LINE 발송 비의도 노출/실메시지 발송 징후 발견
- [ ] production 민감정보 노출 징후(토큰 노출, .env 스니펫 노출) 발생
- [ ] 위 중단 기준 1개 이상 발생 시 데모 즉시 중단 후 운영진 승인 전 재개 금지

## 10. 데모 후 기록할 피드백 항목
- [ ] 데모 소요 시간(10분/30분 플로우 각 단계) 기준치 초과 여부
- [ ] 사용자 반응: 이해도, 화면 흐름 난이도, 추가 요청사항
- [ ] 기능별 체감 문제(매장 생성, owner 로그인, 주문/수리/구매확인, Free/Premium 비교)
- [ ] 데모 중 발생한 이슈 및 회피/우회 조치
- [ ] 다음 데모/파일럿 적용시 우선 개선 항목(POC 우선순위 1~3)
- [ ] 데모 담당자 서명/승인 시간 기록 후 운영팀 공유

## 11. 플랫폼 관리자 계정 준비 확인(레코드)
- [ ] 대상 DB: staging MySQL (3306 컨테이너 포트 3310)
- [ ] 대상 계정: `admin@kingway.tw`
- [ ] SELECT 결과: `id=1`, `role=PLATFORM_OWNER`, `is_active=1`, `password_hash` 존재
- [ ] 작업: is_active=1 조건 충족 시 platform admin 비밀번호 해시 갱신 완료
- [ ] `POST /api/platform-auth/login`(staging API 3010) 응답 200 확인
- [ ] `GET /api/saas-admin/stores` 응답 200 확인
- [ ] raw password/token 출력·기록 없이 처리
- [ ] platform admin password reset performed

- [ ] 데모 중단 기준 미발생 상태로 최종 승인
- [ ] demo 진행 결과 및 피드백을 회의록에 즉시 반영
