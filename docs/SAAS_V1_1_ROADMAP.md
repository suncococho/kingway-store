# SaaS v1.1 로드맵

작성일: 2026-06-04  
브랜치: `beta/staging-architecture`
기준 문서: `SAAS_V1_FINAL_LAUNCH_CHECKLIST.md`, `SAAS_PILOT_STORE_FEEDBACK_FORM.md`, `SAAS_PILOT_STORE_OUTREACH_MESSAGE.md`, `SAAS_V1_REHEARSAL_FINAL_REPORT.md`

## 1) v1.0 완료 범위

1. SaaS 플랫폼 관리/점포 생성 기본 골격
- 플랫폼 admin 로그인/권한 체계와 점포 생성 API (`POST /api/saas-admin/stores`)를 통한 owner/features 동시 생성

2. 멀티테넌시 핵심 기능
- store 기반 API/화면 동작, store 분리 정책 적용
- store=1, store=5 교차침투 차단 사례 검증

3. 기본 운영 흐름
- 매장 설정, LINE 설정, 상품 생성, 주문/POS, 수리예약, purchase-confirm 흐름
- store scoped 공개 flow (`/line-order`, `/repair-reservation`, `/purchase-confirm/:token`)

4. 보안/격리 기반 완화
- Repair 상태 변경/estimate/customer-response의 store_id 하드닝
- 상품 이미지 접근 분기 조치 (`/files/products/*` 직접 접근 차단, 게이트 라우트 사용)

5. Free/Premium 정책
- 메뉴/직접 URL 접근 제어 기본 동작
- store_features 기반 수동 토글 동작 검증

6. 운영 제약 정립
- production/real LINE 발송 미동작 조건, raw token 노출 금지, 민감정보 보안
- staging 기준 smoke regression (`PASS=16 / FAIL=0 / SKIP=0`)

## 2) 파일럿 후 예상 요청 기능

1. 매장 운영에서 가장 즉시 필요한 항목
- 고객 관리(CRM) 상세 보강: CRM stage, follow-up 이력, 주문/수리 히스토리 통합 화면
- 주문/POS 품질 개선: 상태 정합성, 주문 수정 이력, PDF 영수증 링크 정리
- 직관적인 수리예약-수리완료 연동 보강

2. 운영 조직 확장 요구
- staff 권한 분리: 역할별 접근 제어와 화면/메뉴 노출 일치
- 내부 알림/보고 효율성: 재고 알림, 매출 요약, 미처리 건 추적

3. 성장 대비 확장 요구
- 구매확인 고도화: 재시도 링크/변경 이력/이중 인증 형태의 운영 신뢰성 향상
- 공급망 연동과 쿠폰 정책의 현장 반영 편의성 강화

## 3) 우선순위 HIGH

### 3-1. 고객 관리(CRM)
- 목표: 매장 오너/스태프가 고객 정보를 한 화면에서 관리
- 범위: 고객 기본정보, 연락 이력, 주문/수리/쿠폰/설문 이력 통합 뷰
- 개발 난이도: 높음 (기존 주문/고객/수리 테이블 정합 필요)
- 예상 효과: 영업 리드 전환율 향상, 재방문 캠페인 설계 기반 확보

### 3-2. 직원 권한 세분화
- 목표: owner/admin/staff 간 최소권한 적용 및 오작동 사고 감소
- 범위: 메뉴/버튼/직접 API 라우트 권한 정책 통합
- 개발 난이도: 높음 (권한 스키마 + 프론트/백엔드 동기화)
- 예상 효과: 실수/정보유출 리스크 감소, 역할별 책임 영역 선명화

### 3-3. 매출 대시보드
- 목표: 당일/주간/월간 매출 현황을 매장 운영자가 즉시 확인
- 범위: 매출액, 주문건수, 수리비, 결제잔액 상태 위젯
- 개발 난이도: 중간~높음 (집계 API + 시계열 캐싱)
- 예상 효과: 의사결정 속도 향상, 운영 회의 시간 단축

### 3-4. 재고 알림
- 목표: 저재고·품절 사전 탐지
- 범위: 임계치 기준 경고, 알림 히스토리, 주문/수리 연동 재고 감쇠
- 개발 난이도: 중간 (inventory/주문 흐름 연계)
- 예상 효과: 품절 매출 손실 감소, 발주 계획 정확도 증가

### 3-5. 구매확인 고도화
- 목표: 구매확인 절차 완성도 상승
- 범위: 만료/재발급/무효 처리, 서명 검증 흐름 강건화, 고객 재접근 UX 개선
- 개발 난이도: 중간
- 예상 효과: 구매확인 미완료 건 감소, 이탈률 저감

## 4) 우선순위 MEDIUM

### 4-1. supplier 기능
- 목표: 발주/반품/승인 흐름 정규화
- 범위: supplier 등록·발주·승인 상태 이력·월정산 연결
- 개발 난이도: 중간
- 예상 효과: 수리/상품 조달 속도 개선

### 4-2. 쿠폰 확장
- 목표: 프로모션 운영 효율성 강화
- 범위: 쿠폰 정책 템플릿, 사용/기간/대상 조건 강화, 분석 지표
- 개발 난이도: 중간
- 예상 효과: 재구매 촉진과 주문 단가 제고

### 4-3. Telegram 운영도구
- 목표: 운영팀 내부 대응 속도 향상(문서 기반 공지/운영 툴 보조)
- 범위: 내부 알림 모니터링 보조 채널 연동 및 로그 알림 템플릿
- 개발 난이도: 중간
- 예상 효과: 운영 대응 속도 개선
- 비고: 사용자 고객 채널로 대체하지 않으며 LINE-first 원칙에 영향 없음

## 5) 우선순위 LOW

### 5-1. 앱
- 목표: 모바일/오프라인 접근 보완
- 범위: 핵심 기능의 앱형 패널 또는 하이브리드 접근
- 개발 난이도: 높음
- 예상 효과: 특수 환경 운영 유연성 향상

### 5-2. GPS
- 목표: 서비스 보조 데이터(상점/배송/기사 연동) 확장
- 범위: 위치기반 예약 분배 또는 내부 자산 추적 보조
- 개발 난이도: 높음(3rd party 의존)
- 예상 효과: 부가 기능으로서 운영 효율 개선 여지

### 5-3. AI 기능
- 목표: 메시지 초안/분류 추천/문구 자동화 보조
- 범위: 고객 메모 요약, FAQ 제안, 재구매 추천 보조
- 개발 난이도: 높음(데이터/모델 운영비)
- 예상 효과: 사장/스태프 생산성 보조

## 6) 개발 난이도 정리

| 난이도 | 항목 | 예상 소요(스프린트 기준) |
|---|---|---|
| 높음 | 고객 관리, 직원 권한 세분화, 앱 | 3~5 |
| 중간 | 매출 대시보드, 재고 알림, 구매확인 고도화, supplier, 쿠폰, Telegram 운영도구 | 2~4 |
| 낮음~중간 | 운영 문구 정비, 소규모 UX 조정 | 1~2 |

## 7) 예상 효과 정량 지표

- 데모 성공률: 현재 `100%`(16/16) 유지 + 기능 안정성 저하 최소화
- 파일럿 만족도: “도입 의향” 항목에서 조건부 이상으로 전환율 개선
- 운영 효율성: 
  - 주문/수리 응대 대기시간 20~30% 단축
  - 재고 이탈(품절) 케이스 감소
  - 구매확인 미완료 이탈률 감소
- 보안/운영 신뢰도: store 간 침투 0건, raw token/PII 유출 0건 유지

## 8) v1.1 목표

- 파일럿 매장에서 수집한 피드백 기반 `핵심 운영 완성도` 달성
- `CRM + staff 권한 + 매출 대시보드 + 재고 알림 + 구매확인 고도화`를 기준 핵심 번들로 묶어 운영 배포 전 안정화
- staging demo를 유지한 채, production 이전 전환 조건을 충족하는 내부 기준 정합성 강화
- production 준비도 문서에서 “NOT READY” 항목 감축을 시작점으로 삼음

## 9) v1.2 후보

- supplier/쿠폰 고도화 후 연계 모듈화
- 매장 단위 정산·월간 리포트 통합
- 정교한 알림 라우팅(내부 장애 대응, 작업 우선순위 대시보드)
- 구매확인/LINE UX 다국어/지역화 강화(필요시)
- 앱형 경량 UI(현업 워크플로우 중심)

## 10) 100개 매장 목표 단계

1. 단계 0 (현재)
- 기준: 파일럿 스토어 1개 + staging demo stable
- KPI: v1.0 핵심 플로우 안정, `PASS=16/0/0`

2. 단계 1: 5개 파일럿
- 대상: 유사 업종 파일럿 2~5개
- 조건: HIGH 항목 중 최소 3개(CRM/권한/매출대시보드) 기능 동작

3. 단계 2: 20개 파일럿 누적
- 조건: 스테이징 실패율 0 유지, 운영지표 누적 분석 기반 회귀 강화
- 액션: 자동 회귀 패키지 고도화(교차침투/공개 flow/파일 접근)

4. 단계 3: 50개 확대
- 조건: staff 권한 체계와 재고 알림 실사용 안정화
- 액션: 교육 템플릿 표준화, 내부 지원 티켓 SLA 정의

5. 단계 4: 100개 상용 운영
- 조건: production readiness checklist의 핵심 블로커 0건 정리
- 조건: 데이터 마이그레이션·보안·LINE 실운영 승인 동시 완료
- 목표: 운영팀 주도 onboarding, 사후 이탈 리스크 대시보드 운영

## 11) 실행 원칙

- LINE-first 운영 흐름은 유지
- 실제 LINE 발송/토큰/`production .env`는 문서/운영 절차에서 노출 금지
- 코드 수정 없이 문서/운영 기준으로 먼저 정합 확인 후, v1.1 개발 반영
- 파일럿 피드백 폼 항목(기능 반응, 불편 포인트, 다음 우선순위)을 다음 스프린트 기획의 출입구로 사용
