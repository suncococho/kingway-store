# 功能與非功能需求（160 項）

以下需求以 `Rxxx` 作為追蹤 ID；第一版實作前必須再標註 MVP/後續與驗收案例。

## 人員、門市與期間

- R001 系統必須以 `store_id` 隔離班表資料。
- R002 僅啟用中的 `staff_users` 可成為候選人。
- R003 候選人必須有有效 `store_memberships`。
- R004 必須保存員工工作角色與門市角色快照。
- R005 必須支援每店不同時區，預設 Asia/Taipei。
- R006 排班週期預設週一至週日。
- R007 必須可查看目前週、下週與歷史週期。
- R008 週期必須有明確輸入截止時間。
- R009 截止後一般員工不可直接修改已凍結輸入。
- R010 管理者代填必須記錄代填者與理由。

## 營業日曆與 coverage

- R011 週一必須設定為休店日。
- R012 週一不得生成一般營業班次。
- R013 週二至週五同時在班人數必須為 1。
- R014 週六與週日同時在班人數必須為 2。
- R015 每個營業時間片不得出現空班。
- R016 營業開始與結束時間必須可由門市政策設定。
- R017 特殊休店日必須可設定。
- R018 特殊營業日必須可覆寫週間規則。
- R019 coverage 驗證必須以時間片而非只計人次。
- R020 未達 coverage 時禁止發布。
- R021 超過需求人數時必須提示成本與公平影響。
- R022 開店前與關店後任務時間可納入班次。
- R023 跨午夜班次必須明確支援或明確禁止。
- R024 日曆異動必須建立新版本。
- R025 已開始日期的日曆不得無稽核地回改。

## 員工自主輸入

- R026 員工可提交可上班日期與時段。
- R027 員工可提交偏好上班時段。
- R028 員工可提交希望避免的時段。
- R029 員工可提交整日不可上班。
- R030 不可上班原因可選擇不向同事公開。
- R031 敏感原因不得進入評分。
- R032 員工可在截止前修改輸入。
- R033 修改必須保留 revision history。
- R034 系統必須顯示尚未提交狀態。
- R035 系統必須提醒輸入即將截止。
- R036 員工可複製上週可用時段。
- R037 複製後仍需明確確認提交。
- R038 重疊或無效時段必須即時驗證。
- R039 員工只能編輯自己的輸入。
- R040 管理者可查看門市整體 availability heatmap。

## 班次與資格

- R041 班次必須有開始、結束、店別與日期。
- R042 班次可引用可版本化模板。
- R043 同一員工班次不可重疊。
- R044 必須檢查最短休息間隔。
- R045 必須檢查每日最大工時。
- R046 必須檢查每週最大工時。
- R047 必須檢查連續工作日上限。
- R048 可設定開店資格。
- R049 可設定關店資格。
- R050 可設定維修等技能資格。
- R051 技能必須有有效期間。
- R052 過期技能不得滿足 hard constraint。
- R053 新進員工可標記需與資深員工同班。
- R054 不得以未定義角色推定敏感個人能力。
- R055 管理者 override hard constraint 必須被禁止或走特別核准。

## A~E 與綜合分數

- R056 必須計算 A 出勤可靠度。
- R057 必須計算 B 任務完成度。
- R058 必須計算 C 服務與營運品質。
- R059 必須計算 D 協作與責任。
- R060 必須計算 E 技能與班次適配。
- R061 每項分數範圍為 0 至 100。
- R062 必須依版本化權重計算綜合分數。
- R063 預設權重為 A25/B20/C20/D15/E20。
- R064 每項必須顯示資料期間。
- R065 每項必須顯示樣本數。
- R066 每項必須顯示 confidence。
- R067 每項必須提供 reason codes。
- R068 缺資料不得自動當作 0 分。
- R069 核准請假不得降低 A 分數。
- R070 系統故障事件不得降低分數。
- R071 主觀評語不得未經核實直接計分。
- R072 人工調整必須保存前後值與理由。
- R073 員工可查看自己的分數明細。
- R074 員工可提出分數異議。
- R075 異議處理必須有狀態與回覆期限。
- R076 分數快照不得被後續重算覆寫。
- R077 相同來源事件不得重複計分。
- R078 分數不得直接觸發扣薪或懲處。
- R079 管理者可比較期間趨勢但不得公開羞辱排名。
- R080 排班理由必須說明分數實際影響。

## 公平與週末優先權

- R081 必須分別追蹤週六與週日班次。
- R082 必須追蹤滾動 8 週週末機會。
- R083 必須建立週末機會債務 ledger。
- R084 可上班但未獲排班者應累積機會債務。
- R085 自願拒絕週末者不應累積同等債務。
- R086 核准不可上班不應被視為懲罰。
- R087 新進員工採中立起始值。
- R088 高分者不得永久壟斷週末班。
- R089 低分者不得永久失去改善機會。
- R090 週末優先權必須可向員工解釋。
- R091 同分時先比較週末機會債務。
- R092 再比較近期總工時較少者。
- R093 再比較明示偏好。
- R094 最終 tie-break 必須 deterministic。
- R095 管理者改變週末排序必須填理由。
- R096 必須監控週末分配最大差距。
- R097 必須監控偏好滿足率。
- R098 必須能排除非自願/非合格候選人後再算公平。
- R099 公平報表不得洩漏私人不可上班原因。
- R100 公平政策變更只能影響新排班版本。

## 產生、驗證與發布

- R101 系統可為指定週期產生草稿。
- R102 產生前必須凍結 input snapshot。
- R103 草稿必須保存 engine/policy version。
- R104 草稿必須保存 input hash 與 seed。
- R105 相同輸入必須可重現相同結果。
- R106 每個指派必須有 explanation。
- R107 無解時必須回傳具體衝突時段。
- R108 無解時不得偷偷放寬 hard constraint。
- R109 管理者可拖曳或表單調整草稿。
- R110 每次調整後必須重新驗證。
- R111 發布必須使用 optimistic version check。
- R112 只有具發布權限者可發布。
- R113 正式班表必須有發布者與時間。
- R114 新發布 revision 必須 supersede 舊版。
- R115 歷史正式版本必須唯讀可查。
- R116 班次開始後不得一般刪除。
- R117 緊急變更必須記錄原因。
- R118 發布後員工必須可確認已讀。
- R119 未確認名單必須可追蹤。
- R120 匯出內容必須與正式 revision 一致。

## 換班與缺勤

- R121 員工可對自己的未開始班次提出換班。
- R122 換班可指定接班人或公開徵求。
- R123 接班人必須明確同意。
- R124 接班人必須符合 availability、工時與技能。
- R125 換班後 coverage 不得降低。
- R126 管理者必須核准正式換班。
- R127 換班狀態包含待接班、待核准、核准、拒絕、取消、逾期。
- R128 拒絕必須可填理由。
- R129 換班操作必須完整 audit。
- R130 換班核准後建立新 schedule revision。
- R131 緊急缺勤必須觸發候補通知。
- R132 候補接受採原子 claim，避免多人搶同班。
- R133 未補到人時立即升級通知管理者。
- R134 缺勤原因隱私必須受控。
- R135 換班履約才可形成 D 項正向事件。

## 出勤、通知、權限與稽核

- R136 打卡必須關聯正式 `shift_id` 或記錄未排班打卡。
- R137 必須比對預定與實際時間。
- R138 遲到、早退、缺卡、缺勤必須形成待確認異常。
- R139 管理者更正出勤必須記錄原值與理由。
- R140 現有 `/api/attendance/check-in` 與 check-out 必須保持相容。
- R141 發布、異動、換班、缺口可產生 POS 通知。
- R142 重要事件可通知門市員工/管理者 LINE 群組。
- R143 LINE 發送必須使用門市 token/channel resolver。
- R144 通知必須有 idempotency key。
- R145 LINE 發送失敗不得回滾正式班表交易。
- R146 員工只能看自己的私人輸入與班次。
- R147 管理者只能管理有 membership 的門市。
- R148 owner/admin 可管理政策，manager 可依授權排班。
- R149 menu 可見權限與 action 權限必須分離。
- R150 所有變更必須寫 append-only audit log。

## 非功能、測試與合規

- R151 所有可見文案必須為台灣繁體中文。
- R152 核心流程必須支援手機與桌面。
- R153 一週 50 人規模產生草稿目標小於 5 秒。
- R154 API 必須驗證 store scope 與 CSRF/token 既有策略。
- R155 日期時間必須明確處理 Asia/Taipei 與 UTC 儲存策略。
- R156 migration 上 production 前必須備份、dry-run 與回滾演練。
- R157 不得自動寫入 production DB。
- R158 必須有單元、整合、constraint/property、E2E 與權限測試。
- R159 敏感欄位必須最小化、限制存取並設定保存期。
- R160 Phase 0 僅交付分析與設計文件，不得修改應用程式或 DB。
